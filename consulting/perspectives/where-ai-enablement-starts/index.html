Where AI enablement starts, and it isn’t the model

AI initiatives usually stall for the same unglamorous reason: the data and governance underneath weren’t ready. That’s where the useful work begins.

By Anthony PatersonPublished 25 September 20262 min read

On this page

  2. Governance is what lets AI scale
  3. Be specific about the risk
  4. Start with the decision, not the technology
  5. Small, governed steps

Conversations about AI enablement tend to start with model selection: which model, which vendor, which use case to pilot. That’s rarely where the value or the risk sits. By the time an organisation is choosing between models, the outcome has often been decided by earlier choices about data quality, access and governance.

The prerequisite nobody wants to fund

An AI system is only as reliable as the data it can see. Fragmented systems, inconsistent definitions and unclear data ownership don’t disappear because a model is capable. They’re amplified, faster and at scale. Organisations that skip this work tend to get an impressive pilot and a stalled rollout, because the pilot ran on curated data that production can’t match.

Governance is what lets AI scale

The difference between a pilot that stays a pilot and one that becomes part of daily work is almost always governance: clear decision rights over what the system can act on, human review where the consequences warrant it, and traceability when an output needs to be checked. This isn’t bureaucracy. It’s what allows people to trust an output enough to rely on it.

Be specific about the risk

Not every AI use case needs the same level of control. Summarising internal documents for a team that will read the originals anyway is very different from generating advice that a member of the public will act on. Proportionate governance starts by being specific about who relies on the output, what they’ll do with it, and what happens if it’s wrong. That conversation is more useful than any generic AI policy.

Start with the decision, not the technology

A more useful starting question than “where can we use AI?” is “which decisions are currently slow, inconsistent or poorly informed, and would better information change them?” That framing surfaces the data and governance work that has to come first, and it keeps the initiative tied to an organisational outcome rather than a technology demonstration.

Small, governed steps

AI enablement done well looks less like a transformation program and more like a series of governed steps: fix the data a specific decision depends on, put review and traceability around the first use case, show that it works, then extend it. Adoption over theory.
